# What centrion needs on Windows that the stdlib does not have. WINDOWS.md §3.
#
# The Mac keeps its zero-dependency stack — SPEC.md §3's "stdlib only" was a defence against
# brew churn and it still holds there. It does not survive the ConPTY problem here, and the
# honest answer is a venv with a lockfile rather than three optional imports. Every one of
# these is a wheel; nothing compiles on install. `windows\install.ps1` (W5a) builds the venv
# from this file, and on this box the suite is run with `.venv\Scripts\python -m unittest -q`.
#
# Pinned to what was measured on this box, not to a range: a compiled wheel that changes under
# a bot which starts bypass-permissions shells is not something to find out about on a Monday.

# W2b — the config file's secrecy check. NTFS has no mode bits, so `stat.S_IMODE` answers 0666
# for every file and the Mac's 0600 check cannot be ported; the answer is in the DACL, and
# win32security is how it is read. config.py imports it lazily, inside the check, so `import
# config` still works without it — but a config file will not load, because a permission
# check that cannot read the permissions has to fail closed.
pywin32==312

# W0a, and load-bearing since W3b — the ConPTY binding, imported by session_win.Terminal. The
# stdlib has none, and window size must be set before the child exists (WINDOWS.md §6), which
# this does as a constructor argument. Two things about 3.0.5 that the code works around and a
# newer version might not need: it decodes the terminal to `str` and takes `str` to write, so
# `Terminal` re-encodes both ways (§4 asks for the raw-bytes API if one ever appears), and its
# `write` returns 0 for a write that arrived whole, so the return value is not usable.
pywinpty==3.0.5

# W4a wants this for `alive` and `started` — the two halves of §4's pid-reuse guard — and W3e
# needed it first, which is worth saying because the plan had it arriving with the listener.
# W3e's `terminate` has to prove it killed a *tree*, and the pids of that tree are the only
# evidence that survives the kill: they have to be collected before it and asked about after,
# and `psutil.Process(pid).children(recursive=True)` is the only way to walk a parent-child
# relationship on Windows without shelling out to WMI. `tasklist` cannot answer it — it has no
# parent-pid column — and asking the Job Object itself would be verifying the mechanism with
# the mechanism. So this arrives one slice early, in the tests before the code.
psutil==7.2.2
